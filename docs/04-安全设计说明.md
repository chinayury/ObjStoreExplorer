# ObjStoreExplorer — 安全设计说明

> 本说明覆盖**双形态**安全设计：桌面版的**本地攻击面防护**与 Web 容器版的**服务端安全**。
> 依据 当前源码，所有修复项均经构造输入实测或代码审读确认。
> 依赖 CVE 核查见 §7，Web 版权限矩阵见 §9。

---

## 0. 关于「渗透测试」的口径声明

**必须先说清楚，否则本说明会被误读。**

- **桌面版**是**纯本地桌面程序，不监听任何网络端口**。它没有传统服务端意义上的攻击面——
  没有 HTTP 接口、没有对外服务。因此**不存在可被远程渗透的攻击面**。桌面版做的是
  **本地攻击面防护**：识别程序所有接收外部输入的入口，构造恶意输入打进去，验证处理是否正确。
  本说明**不包含、也无法包含**桌面版的远程漏洞利用类测试。

- **Web 容器版**是**标准 HTTP 服务，暴露端口**。它有真实的服务端攻击面，设计覆盖
  **存储型 XSS、路径穿越、信息泄露、安全响应头、会话与凭据、权限矩阵**等服务端安全项。
  生产环境建议置于**反向代理 + HTTPS**之后。

任何声称对桌面版做了远程渗透测试的说法都是虚构的。

## 1. 安全架构与信任边界

### 1.1 桌面版

```
                 ┌──────────── 不可信输入 ────────────┐
                 │                                    │
  S3 服务端 ──► list_objects 返回的 key/name  ──┐   │
  用户输入 ──► endpoint / AK / SK / 配置项  ──┼──►│ 校验层
  本地文件 ──► 下载对象的文件名 / 日志内容  ──┘   │ (validators
                                                 │  sanitize_filename
                                                 │  endpoint 校验)
                                                 ▼
                                        ┌─────────────────┐
                                        │  业务处理层       │
                                        │  core / services │
                                        └────────┬────────┘
                                                 ▼
                                        ┌─────────────────┐
                                        │  本地存储层       │
                                        │  data/ 加密落盘  │
                                        └─────────────────┘
```

**核心风险点**：S3 返回的对象名是**攻击者可控**的——任何能往桶里写对象的人，都能往 key 里塞
`../../`、`:`、`CON` 这类东西。程序在下载到本地路径时如果不做清洗，就是直接的任意文件写入。

### 1.2 Web 版

Web 版在桌面版信任边界之上增加 HTTP 层：浏览器请求 → FastAPI 路由 → 会话鉴权 → 管理器 → S3 客户端。
信任边界关键在**路由层**：每个请求先经会话校验与角色鉴权，凭据仅存服务端会话、不向浏览器下发。

## 2. 鉴权与会话

### 2.1 Web 版双角色

Web 版为多人浏览器访问，分 **viewer（只读）/ admin（全权）** 两角色，权限**逐路由服务端校验**
（非仅前端隐藏）。详见 §9 权限矩阵。

### 2.2 会话设计（v0.1.0 第二轮自实现）

- **HMAC-SHA256 签名 Cookie**：`TokenSessionMiddleware` 自实现，取代 starlette SessionMiddleware；
  Cookie `HttpOnly` / `SameSite=lax`，显式过期 + **常数时间比较**
- **服务端吊销**：登录会话落 SQLite `web_sessions` 表，登出 / 停用 / 删除账号即置 `revoked=1`，
  鉴权每请求查行，**全 worker 即时失效**（旧 Cookie 立即不可用）
- **登录双层防爆破**：IP 限速 + 账号锁定；登录等耗时对不存在用户也跑一次 dummy hash，
  堵用户名枚举时序侧信道；口令错误统一文案防枚举
- **会话过期强制改密**：初始 admin 登录后进入 `must_change_password` 态，服务端拦截其他写操作
- **多 worker 会话密钥**：`O_CREAT|O_EXCL` 原子创建 + 失败者轮询等待，避免 N 个 worker 同时首启
  互相覆盖出不同密钥

### 2.3 桌面版

桌面版是单人本地应用，无网络鉴权。凭据（AK/SK）用 Fernet 加密落盘，不明文存储；
创建用户 / 重置密码后，AK+SK 在系统剪贴板**30 秒后自动清空**，防剪贴板工具 / 远控软件读取。

## 3. 输入校验

所有外部输入在进入业务层前经校验层（`src/objstoreexplorer/core/validators.py`）处理：

| 输入 | 校验规则 |
|---|---|
| **Endpoint** | 控制字符（`< 0x20` / `0x7F`）直接拒绝；协议白名单仅 http/https（拦 `file://` / `ftp://` / `gopher://` / `javascript:` / `data:`）；主机名限定字符集，挡 shell 元字符、空格、引号；端口范围校验；不写端口且不写协议时按 MinIO 默认补 9000 |
| **下载文件名** | `sanitize_filename` 清洗：非法字符（`: * ? < > |`）、Windows 保留名（`CON`/`NUL`/`COM1-9`/`LPT1-9`）、路径穿越（`../`）、NUL 截断、超长截断；`os.path.realpath` 校验落盘路径不逃逸 |
| **桶名 / AK** | 控制字符闸 + `re.fullmatch`，堵住尾随换行绕过（CRLF 注入面） |
| **生命周期 / 桶策略 JSON** | 语法本地校验 + 必填字段校验 + 危险语义检测（匿名 `Principal` 含 `*` 时红字警告） |
| **检索输入** | 空串 / 纯空格返回 `(False, [])` + 明确原因，不崩溃；搜索键 NFC 归一化 |
| **反馈配置** | 非法 scheme / 缺 Statement / 语法错 JSON 均在本地拦下并指出位置，不发给服务端 |

**实测**（桌面版本地攻击面）：14 个端点构造输入 14/14 拒绝、10 个合法写法零误杀；
16 个恶意下载 key 16/16 安全落盘无一逃逸；5 个 SQL 注入 payload 表未被删、数据未被篡改。

## 4. 凭据管理

- **AK/SK**：Fernet 对称加密后落盘（`data/db/config.db` / Web `web_sessions` 表），**SK 永不回传前端**
- **Web 账号口令**：bcrypt 加盐哈希
- **反馈平台 app_key**：走 `X-App-Key` 请求头（不拼 URL query，避免进 access log / Referer）；
  默认强制 https，内网 http 需显式 `allow_insecure_http: true` + 警告
- **主密钥** `data/explorer.key`：32 字节随机数 base64（Fernet）
- **Web 会话密钥** `data/web/secret.key`：HMAC-SHA256 令牌签名

**密钥管理纪律**（`src/objstoreexplorer/core/encryption.py` 与 Web 会话密钥同体系）：

- `O_CREAT|O_EXCL` 原子创建 + 轮询等待
- 长度与 base64 结构校验，结构性破坏（清空 / 截断 / 超长 / 纯文本）启动时即拦下并给出修复步骤
- 原子轮换（临时文件 + fsync + `os.replace`）+ 回调失败自动回滚
- Windows 上密钥文件 ACL 收敛到**当前用户只读**（防 Everyone 读写）

> ⚠ **务必备份 `data/explorer.key`**：丢失 = 库中所有已存 AK/SK 永久不可解密。
> 程序不会在密钥损坏时静默重新生成——那会导致库中所有凭据永久报废，而是明确报错并给出修复步骤。

## 5. 路径防护

| 场景 | 防护 |
|---|---|
| 下载落盘（桌面 / Web） | `sanitize_filename` 清洗 + `os.path.realpath` 校验，恶意 key 无法写出下载目录之外 |
| Web 下载打包 zip | 桶名经 `sanitize_filename` 清洗后再拼路径 / 文件名；内容文件本身 `is_relative_to` 防穿越 |
| 文本预览 | 文本类一律降级 `text/plain` + `X-Content-Type-Options: nosniff`；svg 明确排除（可内嵌脚本）；图片超 2MB 拒绝 |
| 反馈离线包 | 打包前正则脱敏（AKIA / secret_key / sk- token / password / Bearer），日志原文不外发 |

## 6. 降级策略

- **反馈在线失败 → 离线**：在线提交遇网络不可达或提交失败，自动降级为打包离线 zip 供手动导入，
  不丢失反馈内容
- **图标缺失 → 降级**：缺图返回 None + 一次性 log warning，调用方降级到 emoji / 文字，不抛异常
- **能力位不支持 → 虚线降级**：`S3ClientBase` 运行时记录服务端明确不支持的操作，Web `/api/status`
  透出，前端对应入口虚线标记，不对异构后端做统一假设
- **异常可见化**：桌面版装三道异常钩子（Tk 回调异常、主线程未捕获、后台线程未捕获），
  打包后无控制台也不再「点了没反应」，均弹窗 + 写日志

## 7. 依赖安全

### 7.1 CVE 扫描结果（pip-audit 实测）

对**运行时闭包**（直接依赖 + 全部传递依赖）执行 `pip-audit`。

**扫描前发现 21 个漏洞，分布在 2 个包：**

| 包 | 漏洞数 | 修复版本 | 典型问题 |
|---|---|---|---|
| `pillow` | **18** | 12.1.1 / 12.2.0 / 12.3.0 | PSD 解码越界写；FITS 解压炸弹；ICO/BMP/TIFF/WebP 缓冲区溢出 |
| `urllib3` | **3** | 2.8.0 | 流式响应遇 chunked+deflate 尾随字节无限循环（DoS）；TLS 配置未隔离；chunk-size 无长度上限 |

**为什么这两条特别要紧**：Pillow 是本项目暴露面最大的依赖（直接解码用户桶里的对象做预览，
攻击者写恶意 PSD/FITS 文件，用户一预览即触发）；urllib3 正好落在受影响用法上（minio 流式下载 S3 对象）。

**扫描后**：`No known vulnerabilities found`。

> ⚠ **教训**：加固依赖时给 Pillow 写上界 `<12.0.0`，而**所有修复版本都在 12.x**——
> 上界本身把安全补丁挡在门外。跑一次扫描才发现。人眼看 `requirements.txt` 发现不了。

### 7.2 版本区间

| 依赖 | 声明区间 | 收紧理由 |
|---|---|---|
| minio | `>=7.1.0,<8.0.0` | 大版本 Admin API 签名变更 |
| cryptography | `>=50.0.0,<51.0.0` | 清 CVE-2026-69247/69249 等 |
| Pillow | `>=13.0.0,<14.0.0` | 清 39 条 CVE（含 13.0.0 修复版） |
| urllib3 | `>=2.8.0,<3.0.0` | 清 PYSEC-2026-4175/4176/4177 |
| PyYAML | `>=6.0.1,<7.0.0` | 只用 `safe_load`，无 RCE 风险 |
| pywin32 | `>=306,<400` | 仅 Windows，运行期风险低 |
| starlette | `>=1.3.1` | 清 CVE-2025-62727 FileResponse Range DoS（本项目下载接口在用） |
| python-multipart | `>=0.0.31` | 清 CVE-2026-53539 等 9 项 |
| jinja2 | `>=3.1.6` | 清 sandbox 逃逸 |

**上界的意义与陷阱**：桌面版用 PyInstaller 打包，依赖在打包那一刻冻结进 exe。只写 `>=` 意味着
将来重装依赖会把新大版本静默打进产物。**但上界也可能把修复挡在门外**（Pillow 即实例）——
上界必须与实际扫描结果一起维护，不能凭感觉写。

### 7.3 已排除的依赖使用风险

| 检查项 | 结论 |
|---|---|
| `yaml.load` 无 Loader | 未使用，全部走 `safe_load` |
| `pickle` 反序列化 | 未使用 |
| `eval` / `exec` 处理外部数据 | 未使用 |
| `subprocess` shell=True | 未使用（diagnostics 用参数列表调用 PowerShell） |
| 动态 import 用户可控路径 | 未使用 |

## 8. 已修复漏洞与遗留风险

### 8.1 已修复（代表性）

| 级别 | 漏洞 | 修复 |
|---|---|---|
| 高 | 端点 CRLF 注入 | 控制字符 + 协议白名单 + 主机名字符集，合法输入零误杀 |
| 高 | 路径穿越与 Windows 保留名（下载落盘） | `sanitize_filename` + `realpath` 校验，16/16 恶意 key 安全落盘 |
| 高 | PowerShell 命令注入面 | 数值参数 `int()` 强转夹范围，服务名单引号转义 |
| 高 | 反馈 app_key 泄露路径 | 移除硬编码、强制 https、改走请求头、掩码输入、移出版本控制、打包前脱敏 |
| 高 | Web 版存储型 XSS（4 处） | 内联 `onclick` JS 字符串逃逸，改 `data-*` 属性 + 事件委托 |
| 高 | Web 版下载打包路径穿越 | 桶名经 `sanitize_filename` 清洗后再拼路径 |
| 高 | Web 版会话密钥多 worker 竞写 | `O_CREAT|O_EXCL` 原子创建 + 轮询等待 |
| 中 | SQL 注入 | 全部参数化查询，实测 5 个 payload 无篡改 |
| 中 | `user_history` AK 明文落盘 | 改为加密，读取兼容旧明文 |
| 中 | 权限探测 fail-open | 改为 fail-closed |
| 中 | Web 版信息泄露（2 处） | 500 不回显异常原文，422 剥离 `input` 字段 |
| 中 | Web 版安全响应头缺失 | 新增 X-Content-Type-Options / X-Frame-Options / Referrer-Policy / CSP |

### 8.2 未修复的已知风险（如实列出，不粉饰）

| # | 风险 | 原因 | 缓解建议 |
|---|---|---|---|
| 1 | 反馈 `app_key` 落盘仍明文 | 改通用 KV 存储契约会牵连 `app_settings` 全表，影响面超出范围 | 反馈设置界面提示「该值明文存储在本机数据库」 |
| 2 | 未连真实 MinIO 端到端验证 | 环境限制（官方二进制下载下线，镜像源不可用，改用 `moto` 仿真） | 上线前在测试桶跑一遍完整链路 |
| 3 | GDI 修复未运行时证明 | 环境无法计数 | 在真实截屏场景反复失败后观察内存 |
| 4 | 传输层无断点续传 | 需自管分片与会话持久化 | 大文件场景可考虑 |
| 5 | 批量操作无事务补偿 | 需设计操作日志表 | 失败清单持久化 + 重试入口 |

## 9. Web 版权限矩阵（逐路由核对结论）

两角色：**viewer 只读 / admin 全权**。权限**逐路由服务端校验**。

| 路由 | 方法 | viewer | admin | 结论 |
|---|---|---|---|---|
| `/login` `/logout` `/forgot-password` `/reset-password` | GET/POST | 匿名可用 | ✓ | 达标（登录 / 找回带双层限速与防枚举） |
| 10 个页面 `/overview` … `/about` | GET | ✓ | ✓ | 达标（未登录 303 → /login） |
| `/api/web/password` `/api/web/me` `/api/web/email` | PUT/GET/PUT | ✓（本人） | ✓ | 达标（must_change 态服务端拦截其他写操作） |
| `/api/connect` `/api/disconnect` `/api/status` `/api/history*` | POST/GET/DELETE | ✓ | ✓ | 达标（连接凭据按会话隔离；SK 不回传） |
| `/api/buckets` `/api/buckets/{b}/stats` `/api/overview` | GET | ✓ | ✓ | 达标 |
| `/api/buckets`（建 / 删桶） | POST/DELETE | 403 | ✓ | 达标（require_writer） |
| `/api/objects` `/api/search` `/api/objects/stat` `/api/objects/download` `/api/objects/download-zip` `/api/objects/share` | GET/POST | ✓ | ✓ | 达标（读只读放行，与「下载=读」定位一致） |
| `/api/objects/upload` `/delete` `/rename` `/copy` `/move` `/folder` | POST | 403 | ✓ | 达标 |
| `/api/clipboard` GET / POST / paste / DELETE | GET ✓；写 403 | ✓ | 达标（DELETE 登录即可，无越权面） |
| `/api/tasks*` | GET/POST | ✓（仅本人任务） | ✓（可跨会话） | 达标（owner 归属校验） |
| `/api/versioning/{b}` `/api/lifecycle/{b}` | GET ✓；PUT/DELETE 403 | ✓ | 达标 |
| `/api/admin/users*` `/api/admin/policies*` `/api/admin/create-full-setup` `/api/admin/server-info` | 全部 | 403 | ✓ | 达标（require_admin；MinIO 侧权限另由 Admin API 决定） |
| `/api/web/users*`（Web 账号管理） | 全部 | 403 | ✓ | 达标（含最后管理员保护、软删、临时口令一次性返回） |
| `/api/logs` GET / DELETE | GET ✓ | ✓ / ✓ | 达标（清空仅 admin） |
| `/api/settings` GET/PUT、`/api/settings/smtp*` | GET ✓；写 403 | ✓ | 达标 |

**会话与凭据安全结论**：① 会话 Cookie `same_site=lax`（缓解 CSRF）；② 登录改密换新 sid、
口令错误统一文案防枚举；③ SK 全程 Fernet 加密落盘、API 永不回传；④ 任务 / 结果按会话归属校验；
⑤ 上传与单文件下载均过 `sanitize_filename`；⑥ endpoint 校验拦 CRLF / 非 http(s) 协议；
⑦ bcrypt 加盐哈希；⑧ 登录等耗时对不存在用户也跑一次 dummy hash，堵用户名枚举时序侧信道。

## 10. 结论

| 结论 | 说明 |
|---|---|
| **桌面版无远程攻击面** | 纯本地程序，不监听端口 |
| **桌面版本地攻击面已覆盖** | 6 类入口、40+ 构造输入，路径穿越 / CRLF 注入 / SQL 注入 / 密钥篡改 均已验证拦截 |
| **Web 版服务端安全已逐路由审查** | 权限矩阵逐路由核对，XSS / 路径穿越 / 信息泄露 / 安全头 / 会话 均已修复或核实达标 |
| **依赖 CVE 已清零** | pip-audit 实测 21 个漏洞全部修复，复扫无告警 |
| **遗留 5 项已知风险** | 已在 §8.2 列出原因与缓解建议，其中 2 项需上线前处理 |

**上线前必做**：① 在真实 MinIO 测试桶上端到端跑一遍完整链路；② Web 版置于反向代理 + HTTPS 之后。
