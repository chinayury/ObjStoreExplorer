# ObjStoreExplorer — 环境部署教程

> 本文严格依据 当前源码与部署配置编写，覆盖**桌面版**与 **Web 容器版**两种形态的环境要求、
> 安装、目录结构、配置、启动、打包与故障排查。
> 功能使用见 [03-功能使用说明](./03-功能使用说明.md)，安全部署建议见 [04-安全设计说明](./04-安全设计说明.md)。

---

## 1. 环境要求

| 项 | 桌面版 | Web 容器版 |
|---|---|---|
| Python | 3.13（实测 3.14.6 同样通过），需**含 tkinter** 的发行版 | 镜像内置 python:3.13-slim，无需本地 Python |
| 依赖 | `requirements.txt`（minio / cryptography / Pillow / PyYAML / pywin32） | `requirements-web.txt`（在桌面版之上追加 FastAPI / uvicorn / Jinja2 等） |
| 运行时 | 本地 Windows / macOS / Linux | Docker + docker-compose |
| 网络 | 不需要（纯本地，不监听端口） | 需暴露 HTTP 端口（默认宿主 6083） |

**Windows 上 Tkinter 的坑**：`python.org` 官方安装包默认包含 tkinter；Microsoft Store 版、
某些精简第三方 Python **不包含**。检查方法：

```powershell
python -c "import tkinter; print(tkinter.TkVersion)"
```

报 `ModuleNotFoundError: No module named 'tkinter'` 说明装错了 Python，换官方版重装。

## 2. 安装方式

### 2.1 桌面版 · 用打包好的 exe（推荐给最终用户）

1. 下载 `ObjStoreExplorer-<version>-win-x64.zip`
2. 解压到**有写入权限**的目录，例如 `D:\Tools\ObjStoreExplorer\`
3. 双击 `ObjStoreExplorer.exe`
4. 顶部点「连接」，填 Endpoint / AK / SK

> ⚠ **不要解压到 `C:\Program Files\`**。程序会在自己的目录下建 `data/`，只读位置会启动失败。
> ⚠ **立刻备份 `data/explorer.key`**：它丢失 = 库中所有已保存的 AK/SK 永久不可解密。

### 2.2 桌面版 · 从源码运行（开发 / 二次开发）

源码采用 src 布局，推荐先以可编辑模式安装包，再用模块入口启动：

```powershell
# 1. 建虚拟环境
python -m venv .venv
.\.venv\Scripts\Activate.ps1
# 若提示执行策略受限，先放开当前用户：
# Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 2. 装依赖 + 以可编辑模式安装包
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -e .

# 3. 启动（两种方式等价）
python -m objstoreexplorer
# 或直接跑引导壳（自动把 src/ 加入搜索路径，无需先安装）：
python main.py
```

> 内网环境：pip 默认走 PyPI 通常不通，按需加镜像源
> `python -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/`
> 若内网有 HTTP 代理，**先清掉再装**——pip 走代理会反复 timeout 并把"找不到包"写进缓存：
> `$env:HTTP_PROXY=""; $env:HTTPS_PROXY=""; python -m pip cache purge`

### 2.3 Web 容器版 · Docker 部署

本目录自带 `Dockerfile`（FastAPI + uvicorn）、`docker-compose.yml`（pip 源构建参数已内置清华镜像）、
`deploy.sh`（Linux/macOS）/ `deploy.bat`（Windows）。拷走本目录即可单独部署。

```bash
./deploy.sh                 # 一键：创建数据目录 → 构建 → 启动
# 或手动：
docker compose up -d --build
```

浏览器打开 `http://服务器IP:6083`（宿主端口，容器内为 8000；改 `docker-compose.yml`
的 `ports` 左半边可换）。

**初始管理员口令**：

- 未设置 `WEB_ADMIN_PASSWORD` 时，首次启动**随机生成**并打印在日志里：
  ```bash
  docker compose logs objstoreexplorer-web | grep -A2 "初始管理员"
  ```
- 也可在 `docker-compose.yml` 的 `environment` 里显式指定 `WEB_ADMIN_PASSWORD` 后重建。
- **初始口令不再写入轮转日志文件**，唯一出口为 stdout。登录后系统会**强制要求修改初始口令**。

**容器安全基线（非 root 运行）**：

- 容器以专用系统用户 `ose`（uid 10001）运行，compose 已开启只读根文件系统（`read_only: true`）、
  全量 `cap_drop: [ALL]` 与 `no-new-privileges`；运行期可写位置仅 `data` 卷与容器内 `/tmp`（tmpfs）。
- 宿主机 `data` 目录须可被 uid 10001 写入：`deploy.sh` 已自动执行 `chown -R 10001:10001 data`；
  手动部署或从旧版（root 容器）迁移时请先自行执行，否则启动会因无法写 SQLite/日志而失败。

**国内网络构建说明**：

- pip 依赖：compose 已传清华源构建参数（海外服务器删掉 `PIP_INDEX_URL` 那行即可）。
- 基础镜像 `python:3.13-slim` 拉取慢时给 Docker 配 registry-mirror（如 `docker.m.daocloud.io`）。

## 3. 目录与文件结构

### 3.1 源码目录（开发用）

```
project-root/
├── src/objstoreexplorer/          # 包目录 = 发行名
│   ├── __init__.py __main__.py main.py
│   ├── config/  core/  services/  ui/  utils/  webapp/  resources/icons/
├── main.py                        # 桌面版启动引导壳
├── pyproject.toml                 # 构建配置（包名 / 入口点 / 包数据 / 动态版本）
├── requirements.txt  requirements-web.txt
├── Dockerfile  docker-compose.yml  deploy.sh  deploy.bat
├── build.py  build.spec           # 桌面版打包
├── docs/                          # 交付文档
├── README.md  CHANGELOG.md  LICENSE.md  AGENTS.md
└── .env.example                   # 环境变量模板
```

### 3.2 桌面版 exe 解压后目录

```
ObjStoreExplorer/                 ← 程序目录（必须可写）
├── ObjStoreExplorer.exe          主程序
├── _internal/                    PyInstaller 依赖（不要删）
├── data/                         首次运行自动创建
│   ├── explorer.key              ⚠ 加密主密钥，务必备份
│   ├── db/config.db              加密数据库
│   ├── cache/  logs/  temp/  feedback_bundles/
│   └── config/feedback.yaml      反馈配置（可选，用户可编辑）
```

**`data/` 定位规则**：程序以自身可执行文件所在目录为基准（源码运行时是**项目根**）。
用 `OSE_DATA_DIR` 环境变量可重定向——多实例并行、U 盘便携、或源码目录只读时用。

### 3.3 Web 版数据目录

| 宿主机路径 | 内容 |
|---|---|
| `./data` | Web 账号库（web.db）、加密连接历史、操作日志、上传临时目录、会话签名密钥 |

备份 = 打包 `./data` 一个目录；迁移 = 拷走整个项目目录重新 `./deploy.sh`。
**`data/explorer.key` 与 `data/web/secret.key` 必须一并备份**，丢失则已存凭据不可解。

## 4. 配置说明

### 4.1 环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `OSE_DATA_DIR` | 程序目录下的 `data/` | 重定向数据目录（多实例 / 便携 / 只读目录规避） |
| `WEB_ADMIN_PASSWORD` | 随机生成 | Web 容器版：首次启动 admin 初始口令（不设则看日志） |
| `WEB_WORKERS` | 1 | Web 容器版：uvicorn worker 进程数（会话/连接/任务已外置 SQLite，可调大） |

模板见 [.env.example](../.env.example)。程序不自动读 `.env`，需要时在系统/用户环境变量里设置，
或用启动脚本传入。

> v0.1.0 已移除 `OSE_MASTER_KEY`（代码从未读取，属误导性配置项）。

### 4.2 反馈平台配置

反馈平台对接参数存本地数据库（`app_settings` 表），优先级：**数据库 > `data/config/feedback.yaml` > 内置占位**。

- 仓库只提供模板 [`src/objstoreexplorer/config/feedback.yaml.example`](../src/objstoreexplorer/config/feedback.yaml.example)（全占位符）。
- 需要在线反馈时，复制该模板到 **`data/config/feedback.yaml`** 并填写真实 `app_key` / `api_base`。
- 未配置（占位符）时反馈走**离线模式**，生成 zip 供手动导入。
- `api_base` 默认强制 https；内网 http 需在 yaml 显式 `allow_insecure_http: true` 才放行。

### 4.3 多 worker 说明（Web 版）

会话外置化后，`WEB_WORKERS` 可安全调大（在 `docker-compose.yml` 的 `environment` 里设置，
如 `WEB_WORKERS: "2"`）：

- **前提**：`./data` 必须挂在持久卷上（compose 默认满足）——会话签名密钥、账号库、
  连接快照都在这里，worker 之间靠它共享。
- **已外置状态**：登录会话（`web_sessions` 表，可服务端吊销）、S3 连接快照
  （AK/SK Fernet 加密落库，worker 重启或请求落到别的 worker 时按快照重连）、剪贴板、
  传输任务注册表（进度 / 取消标志 / 结果 zip 路径）。
- **仍按进程独立的内存态（有意设计，无正确性影响）**：登录 IP 限速与发码限速为每 worker
  独立计数（阈值实际放大 N 倍；账号级 DB 锁定仍是全局的）；S3 客户端实例为各 worker 私有缓存。
- **调大建议**：仅在单 worker 出现 CPU 饱和（大量并发上传 / 下载统计）时再调；
  I/O 瓶颈（慢 MinIO）调 worker 无益。改完 `docker compose up -d --build` 生效。
- **升级注意**：第二轮起登录令牌格式变更（HMAC-SHA256 自实现），升级后所有用户需重新登录一次；
  `./data` 无破坏性表结构变更，回滚旧镜像即可。

> v0.1.0 已把 MinIO Admin 调用、bcrypt 哈希、SMTP 收发等阻塞操作移出事件循环
> （同步处理器 + FastAPI 线程池），单 worker 下慢 MinIO 不再拖垮其他用户的请求。

### 4.4 常用命令（Web 版）

```bash
docker compose logs -f objstoreexplorer-web   # 看日志
docker compose down                           # 停止
docker compose up -d --build                  # 改配置后重建
```

## 5. 桌面版 · 打包成 exe

```powershell
python -m pip install pyinstaller
python build.py
```

产物在 `dist/`：

| 文件 | 说明 |
|---|---|
| `ObjStoreExplorer/` | onedir 目录（.exe + `_internal/`），**分发整个目录** |
| `ObjStoreExplorer-<version>-win-x64.zip` | 上传用的压缩包 |
| `SHA256SUMS.txt` | 校验和 |

> **为什么是 onedir 而非单文件 exe**：单文件自解压壳是 360 / 火绒 / Defender 的高误报特征
> （银狐木马启发式）。改 onedir 后误报率大幅下降。**不要再改回 onefile，也不要开 UPX**
> ——UPX 压缩壳同样是杀软启发式的高触发特征（`build.spec` 里 `upx=False` 并写了理由）。

**依赖漏洞门禁**：依赖全部声明版本上界并经 `pip-audit` 核查（见 [04-安全设计说明 §7](./04-安全设计说明.md)）。
上界可能挡安全补丁，必须配合扫描核验——v0.1.0 加固时给 Pillow 写上界 `<12.0.0`，
而所有修复版本都在 12.x，**上界本身把安全补丁挡在了门外**。

**版本号唯一真源**是 `src/objstoreexplorer/config/settings.py` 的 `APP_VERSION`。
`build.py` 只从那里读，读不到会**直接报错**，不会静默兜底成别的版本号。

## 6. 故障排查

### 6.1 双击无反应

GUI 程序没有控制台，异常看不见。按顺序排查：

1. **数据目录不可写**——程序会弹窗说明。若无弹窗，改为把程序放到可写目录，或设 `OSE_DATA_DIR`。
2. **缺 `explorer.key` 且目录只读**——同上。
3. **Tcl 初始化失败**——换 `python.org` 官方 Python。

源码运行想看完整报错：`python -m objstoreexplorer`（控制台直接打印 traceback）。
程序已装三道异常钩子：Tk 回调异常、主线程未捕获异常、后台线程未捕获异常，都会弹窗并写日志。

### 6.2 启动报「密钥文件已损坏」

`data/explorer.key` 为空或长度不对（断电、磁盘满、手动编辑过）。程序不会静默重新生成——
那会导致库中所有凭据永久报废。处理：

1. 把 `explorer.key` 改名留档（如 `explorer.key.bak`）
2. 重新启动，程序会生成新密钥
3. 重新填写服务器 AK/SK

若有完好备份，把备份放回原文件名即可恢复旧凭据。

### 6.3 启动报「无法解密：当前密钥与密文不匹配」

三种可能，按概率排序（错误提示里也写了）：

1. `explorer.key` 被删过重建，数据库是旧的 → 旧凭据不可恢复，重填
2. 数据库从别的机器 / 数据目录拷来，两边密钥不同 → 把原机器的 `explorer.key` 一并拷来
3. 数据库文件损坏

### 6.4 连不上对象存储

| 现象 | 排查 |
|---|---|
| "端口必须是数字" | Endpoint 必须写 `host:9000`，别只写 host |
| 连接超时 | 检查网络 / 防火墙；`https://` 结尾的端点若自签证书会失败 |
| `AccessDenied` | AK/SK 无该桶权限 |
| 连上了但界面空 | 顶部状态栏看连接状态；按 F5 刷新 |

**Endpoint 填写规则**（`src/objstoreexplorer/core/validators.py`）：

- 支持 `192.168.1.247:9000`、`http://host:9000`、`https://host`、`host:9000`
- **不写端口且不写协议时，按 MinIO 默认补 9000**（不是 80）。服务在 80 端口必须显式写 `:80`
- 拒绝换行 / 制表符、shell 元字符、`file://` 等非 http(s) 协议

### 6.5 界面卡住

所有耗时操作（列表拉取、传输、同步、统计）均已走后台线程 + 主线程桥，界面不应长时间无响应。若遇到：

1. 看 `data/logs/app.log` 是否有异常
2. 概览页会对**每个桶**做全量统计，桶多时首次加载确实需要时间（副标题已注明）
3. 关闭程序时若有在途传输会先提示确认

### 6.6 Web 版故障

| 现象 | 排查 |
|---|---|
| 容器起不来 | `docker compose logs objstoreexplorer-web` 看报错；常见为 `./data` 权限或端口占用 |
| 忘记 admin 口令 | 见 §2.3：未设 `WEB_ADMIN_PASSWORD` 时查日志；或重建容器重新生成 |
| 登录后被登出 | 会话过期（默认 30 分钟空闲）；多 worker 下确认 `./data` 挂载在持久卷 |
| 上传大文件被拒 | 检查系统设置「单文件上传大小限制」；超限在**落盘前**即拒绝（400） |

## 7. 卸载

**桌面版**：

```powershell
# 1. 删除程序目录
Remove-Item -Recurse -Force D:\Tools\ObjStoreExplorer

# 2. 若设过环境变量，清掉
[Environment]::SetEnvironmentVariable("OSE_DATA_DIR", $null, "User")
```

数据在程序目录的 `data/` 下，删程序目录即全部清除。**删除前确认已备份 `explorer.key`。**

**Web 版**：

```bash
docker compose down        # 停止并删除容器
# 数据保留在 ./data，确认不再需要后手动删除
```
