## 2. 缺陷修复（现象 → 根因 → 解决方案）

v0.1.0 首轮四路并行逐行审计共产生 **201 条发现**，全部处理。以下为代表性条目。

### 2.1 致命缺陷（4 条，全部修复）

**① 修改策略抹掉用户其他权限**

- **现象**：从用户上分离一个策略后，该用户的其他策略与组身份一并消失。
- **根因**：MinIO `detach_policy` 底层是 `SetPolicy`（整体替换），按增量调用等于抹掉其余策略，且无回滚。
- **解决方案**：detach 前快照每个用户完整策略列表与组身份，改完整体写回，失败回滚。
- **验证**：改策略后用户其余策略与组身份完整保留。

**② 重置密码销毁用户**

- **现象**：重置用户密码后，用户消失且组身份丢失。
- **根因**：`user_remove` + `user_add`，`add` 失败时用户已删且组身份未还原。
- **解决方案**：删前校验密钥 + 快照还原 `policyName` 与 `memberOf`。
- **验证**：重置后用户策略与组身份完整还原。

**③ 一键创建返回未生效的随机密码**

- **现象**：目标 AK 已存在时，界面仍展示一个从未生效的随机密码。
- **根因**：随机密码赋值在用户存在性检查之前，已存在分支走跳过但密码仍展示。
- **解决方案**：赋值下移到确认新建后，已存在时显示「用户已存在，密码不可查询」。
- **验证**：已存在 AK 不再返回虚假密码。

**④ 同步必崩**

- **现象**：本地与远端有相同文件时，同步过程抛 `AttributeError` 崩溃。
- **根因**：`SyncPlan` 无 `skipped` 属性，两端相同文件路径访问了不存在的属性。
- **解决方案**：补 `skipped: int = 0`，汇总与 summary 同步。
- **验证**：两端相同文件的同步正常完成，跳过项正确计数。

### 2.2 严重缺陷（代表性）

**Web 删文件夹只删占位对象**

- **现象**：Web 版删除文件夹后，子对象残留而界面报成功。
- **根因**：S3 文件夹是 `/` 结尾 0 字节占位对象，旧实现当普通 key 删，子对象未处理。
- **解决方案**：文件夹走 `delete_folder`（list 展开 + 批量删），文件走线程池。
- **验证**：文件夹删除后子对象全部清除。

**事件循环阻塞（workers=1 关键项）**

- **现象**：慢 MinIO 时，单个用户的操作卡住所有用户所有请求。
- **根因**：30 个 `async def` 处理器函数体是阻塞的 MinIO 调用 / bcrypt / SMTP，阻塞事件循环。
- **解决方案**：全部改同步 `def`，由 FastAPI 线程池执行，阻塞操作移出事件循环。
- **验证**：单 worker 下慢 MinIO 不再拖垮其他用户请求。

**登出后旧 Cookie 仍可用**

- **现象**：用户登出后，旧会话 Cookie 仍能继续访问。
- **根因**：会话仅靠 Cookie 签名校验，服务端无吊销记录。
- **解决方案**：登出 / 停用 / 删号即置 `revoked=1`，鉴权每请求查 `web_sessions` 行，全 worker 即时失效。
- **验证**：登出后旧 Cookie 立即 401。

### 2.3 中等 / 轻微（代表性）

**端点 CRLF 注入**

- **现象**：`evil.com\nX-Injected: 1:9000` 等端点被接受，可注入额外请求头。
- **根因**：endpoint 进入 HTTP `Host` 请求头前未过滤控制字符。
- **解决方案**：解析前检查任何 `< 0x20` / `0x7F` 控制字符直接拒绝；协议白名单仅 http/https；
  主机名限定字符集。合法输入零误杀。
- **验证**：14 个构造端点 14/14 拒绝，10 个合法写法零误杀。

**路径穿越与 Windows 保留名（下载落盘）**

- **现象**：恶意 key 可能写出下载目录之外，或因保留名 / 非法字符落盘失败。
- **根因**：`sanitize_filename` 早已实现但**全库零调用**，设计上缺最后一环。
- **解决方案**：下载落盘统一经 `sanitize_filename` 清洗 + `os.path.realpath` 校验；
  不同目录同名对象自动加 `(2)` `(3)` 后缀，避免静默覆盖丢数据。
- **验证**：16 个恶意 key 16/16 安全落盘，无一逃逸。

**反馈 app_key 泄露路径**

- **现象**：app_key 经源码硬编码、明文传输、URL query、明文界面、版本控制多条路径泄露。
- **根因**：多处历史实现未收敛到统一安全模型。
- **解决方案**：移除硬编码、默认强制 https、改走 `X-App-Key` 请求头、界面掩码、移出版本控制、
  反馈包打包前正则脱敏。
- **验证**：各泄露路径均已封堵，离线包日志脱敏覆盖 AKIA / secret_key / sk- / password / Bearer。

**图标缓存无界**

- **现象**：侧栏 hover / 选中按 tint 生成图标组合，缓存基数随动态颜色无界增长。
- **根因**：`utils/icons.py` 三个字典（缓存 / 缺图 / 告警）无淘汰策略。
- **解决方案**：加 512 上限，`_missing` 加 60s TTL，缺图带 TTL 可自动恢复。
- **验证**：长时间运行内存稳定，缺图资源就位后自动恢复。

## 4. 架构改进

- **跨线程桥**（`ui/threading_bridge.py`）：Tk 非线程安全，所有控件操作经队列回主线程，
  解决 11 处跨线程直接调用控件的随机崩溃
- **单例加锁补全**：`ConfigManager` / `ServiceLocator` 的 `__init__` 加锁，防并发首启互相覆盖
- **惰性导入**：`__init__.py` 版本号惰性转发，`services` 改 PEP 562 惰性导出
- **版本号单一真源**：只认 `config/settings.py:APP_VERSION`，移除 `OSE_VERSION` 覆盖机制
- **性能优化**：对象列表每批 200 行 + 「加载更多」；概览统计带上限 + 截断标记；
  强制删桶流式迭代 + 每 1000 条批量；日志 `deque(maxlen=)` 增量读尾部；
  传输自持 12 线程 + 分批背压

## 5. 本次重组：扁平布局 → 标准 src 布局（2026-11-13）

### 现象

源码采用扁平布局：`config/` `core/` `services/` `ui/` `utils/` `webapp/` `resources/` `main.py`
直接位于项目根，包目录名与发行名不一致，无法以标准可安装包形式交付（`pip install` 后
`import objstoreexplorer` 不成立，`python -m objstoreexplorer` 不可用）。

### 根因

项目早期从单脚本演进而来，沿用根目录即源码根的布局，未收敛到标准 Python 包布局，
导致打包 / 安装 / 入口点自洽性不足。

### 解决方案

1. **结构调整**：将 `config` `core` `services` `ui` `utils` `webapp` `resources` `main.py`
   `__init__.py` `__main__.py` 全部移入 `src/objstoreexplorer/`，包目录名 = 发行名 `objstoreexplorer`。
2. **导入转换**：将 295 处内部绝对导入（`from config.x` / `from core.x` 等）统一转为**包内相对导入**，
   按文件所在目录深度计算相对前缀，确保包内可解析。
3. **路径敏感修复**：
   - `config/settings.py:_get_executable_dir()` 改为向上回溯含 `pyproject.toml` 的项目根
     （原 `parent.parent` 在 src 布局下会把 `data/` 建进包目录）
   - `utils/icons.py:_icon_dir()` 增加 `_MEIPASS` 候选（打包后图标落位 `_MEIPASS/resources/icons`）
   - `utils/feedback_client.py:_resolve_config_path()` 将用户可编辑 `feedback.yaml` 定位改为
     `data/config/feedback.yaml`（数据目录内，不污染源码树）
   - `__main__.py` 的 `from main import main` 改为 `from .main import main`
4. **构建配置**：新建 `pyproject.toml`（包名 / `package-dir=src` / 入口点 `objstoreexplorer.__main__:main` /
   包数据含图标与模板 / 动态版本取自 `objstoreexplorer.__version__`）；
   根 `main.py` 改为启动引导壳（PyInstaller 入口 + 源码直跑，自动把 `src/` 加入搜索路径）。
5. **部署配置更新**：`build.py` / `build.spec` 资源与反馈模板路径改为 `src/objstoreexplorer/...`，
   `pathex` 指向 `src/`；`Dockerfile` 改为 `COPY src ./src` + `pip install --no-deps .`，
   CMD 入口改为 `objstoreexplorer.webapp.main:app`，设 `OSE_DATA_DIR=/app/data`。
6. **清理**：移除 Git / CI / 开发工具类冗余（`.gitignore` `.gitlab-ci.yml` `ci/` `scripts/` `docs-archive/`），
   移除敏感的真实 `config/feedback.yaml`（含 app_key 凭据，安全红线绝不保留，仅留 `.example` 模板）。

### 验证

- `import objstoreexplorer` 成功，`__version__` = 0.1.0（动态版本从 `config/settings.py` 正确读取）
- `from objstoreexplorer.main import main` 可导入，`main` 可调用
- `from objstoreexplorer.webapp.main import app` 可导入并成功创建 FastAPI 应用（14 条路由，
  实跑 `get_state()` 初始化账号库与加密库）
- `python -m objstoreexplorer` 成功启动桌面版 GUI（事件循环正常阻塞，无 stderr 报错）
- 图标路径解析正确：`_icon_dir()` 指向 `src/objstoreexplorer/resources/icons`，189 个图标 + logo.ico 就位
- 无残留内部绝对导入；无 `__pycache__` / 构建产物 / 缓存残留

## 6. 验证结论

### 6.1 静态与编译

- 全部 Python 文件编译通过；模块导入链无循环依赖
- Web 13 个模板 Jinja2 编译通过；2 个 JS `node --check` 通过

### 6.2 S3 端到端（仿真）

服务端用 `moto`（S3 协议兼容实现）起真实 HTTP 服务，客户端走应用实际路径。覆盖：参数校验、
连接、建桶、上传（含中文名 / 空格 / 子目录）、列举、下载、属性 / 标签、桶策略、版本控制、
生命周期、传输服务、搜索、删除、错误路径、断开——全程真实 HTTP + SigV4 签名 + XML 解析。

> **验证局限（如实说明）**：`moto` 的 Admin API 只部分实现，MinIO 特有行为无法覆盖。
> **上线前仍建议在真实 MinIO 上跑一遍**：建桶→上传→下载→改桶策略→重置用户→同步。
