## 三、未采纳及理由（取舍原则备忘）

1. **成本智能**（sairo）：MinIO 自托管无统一定价锚点，仪表盘已有容量统计。
2. **AI 分析/推荐**：与「本地、私有、最小依赖」定位冲突。
3. **TUI 形态**（stu/termscp）：已有桌面+Web 双形态，第三形态无边际收益。
4. **静默自动更新**（rclone selfupdate）：产物未签名，静默替换二进制供应链风险大于收益；只采纳「只检查 + 校验和指引」（要点 5）。
5. **运行时插件市场**（filestash wasm 插件）：单人维护负担过重；只借鉴接口划分思想（要点 6）。
6. **浏览器直连 S3 的 SPA**（tlinhart/s3-browser 等）：凭据必须暴露前端，与「凭据不出服务端」安全基线冲突。
7. **MCP server 接口**：无真实需求信号，入观察名单。
8. **匿名浏览公共桶**（s3manager）：与「显式建立连接」产品口径不符，易被误用于越权枚举。
9. **requester-pays / SSE-C / Glacier 还原**（Pail）：MinIO 场景基本不涉及。
10. **多后端聚合网盘**（CloudPaste）：偏离主轴且许可不明。
11. **国际化全面铺开**：双语成本高收益低，只建机制（要点 7）并设启用闸门。

## 五、2026-11-28 增量复核

### 传输队列的两项交互变化

Pail v0.7.4（11 月 26 日）把正在传输的任务排在暂停和排队任务前面。遇到暂时没有字节流动的阶段，会显示准备、压缩或校验等具体动作。这两项进入观察清单。[Pail 发布说明](https://github.com/DejavuMoe/Pail/releases/tag/v0.7.4)

| 要点 | ObjStoreExplorer 现状 | 取舍 |
|---|---|---|
| 运行中任务置顶 | Web 任务列表按创建时间倒序，较新的任务在前 | 待确认用户寻找运行中任务的需求，再决定是否调整默认顺序 |
| 显示传输阶段 | Web 任务可显示进度和当前文件；单凭字节数停滞无法区分准备和校验 | 待相应执行步骤能提供可靠状态时，再评估界面提示 |
| 批次控制 | 已支持多文件任务，可按任务暂停、继续和取消 | 保留现有控制方式 |

### 其他实现对照

- s3manager 的预签名分享支持外部地址，并拒绝非法有效期。本项目已支持独立分享地址，Web 分享接口对不支持的有效期返回 HTTP 400。[s3manager 发布说明](https://github.com/cloudlena/s3manager/releases/tag/v0.13.0)
- Filestash 修正了 Windows 搜索插件使用 SQLite WAL 的问题。本项目 Web 持久化层已显式设置 WAL，该插件的修复没有直接移植点。[Filestash 提交](https://github.com/mickael-kerjean/filestash/commit/d3bdbde5b9f385b52cf447daba0cc4c13e8e391f)
